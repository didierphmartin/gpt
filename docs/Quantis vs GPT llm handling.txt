  ---
  Key Differences

  1. Dependency Management

  GPT:
  - Uses dependency injection via constructor
  - Accepts Configuration object
  - Clean separation with interfaces (FunctionExecutorInterface,
  UsageTrackerInterface, StreamingClientInterface)

  Quantis:
  - Accepts raw config array
  - Creates HTTP client in constructor
  - Uses global variables ($llm_system, $GLOBALS['sse_hub_client'])

  2. Tool/Function Definitions

  GPT:
  private function getTools(): array {
      return $this->functionExecutor->getToolDefinitions();
  }
  - Tools loaded dynamically via function executor

  Quantis:
  private function loadToolDefinitions() {
      $toolsContent = file_get_contents(__DIR__ . '/../claude_tools.json');
      $this->tools = json_decode($toolsContent, true);
  }
  - Tools loaded from JSON file and cached at initialization
  - Has optimization comments throughout

  3. Function Execution

  GPT:
  private function executeFunction(string $functionName, array $parameters, 
  ?string $userId): array {
      return $this->functionExecutor->execute($functionName, $parameters,
  $userId);
  }
  - Delegates to FunctionExecutor interface

  Quantis:
  private function executeFunction($functionName, $userId, $parameters) {
      switch ($functionName) {
          case 'llm_get_crypto_news':
              $result = call_user_func($functionName, $userId,
  $parameters['source'] ?? null);
              break;
          // ... 30+ more cases
      }
  }
  - Hardcoded switch statement with 30+ function mappings
  - Direct function calls via call_user_func()

  4. Recursion & Tool Use

  GPT:
  private function handleToolUseRecursive(..., int $depth = 0): array {
      if ($depth >= $this->maxRecursionDepth) {
          $this->logger?->warning("Max recursion depth reached");
          return $response;
      }
      // Clean recursive logic
  }

  Quantis:
  private function handleToolUseRecursive(..., $depth = 0) {
      if ($depth > 10) {
          debug_log("⚠️ CLAUDE: Max recursion depth reached (10)", 'warning');
          return "I apologize, but I've reached the maximum...";
      }
      // More verbose with debug logging
  }
  - Hardcoded depth limit of 10
  - Returns user-friendly error message instead of exception

  5. Logging & Debugging

  GPT:
  $this->logger?->logApiRequest('claude', '/v1/messages', $payload);
  - Uses injected DebugLogger class
  - Optional null-safe operator ?->

  Quantis:
  debug_log("🚀 PORTFOLIO CLAUDE: Starting HTTP-first...", 'debug');
  debug_log("✅ CLAUDE: SSE Hub Client initialized", 'debug');
  - Uses global debug_log() function
  - Extensive emoji-based logging (🚀, ✅, ❌, 🔧, etc.)
  - Much more verbose

  6. Unique Features

  GPT Has:
  - ✅ Interface-based design
  - ✅ streamChat() method (stub)
  - ✅ getSupportedModels() method
  - ✅ Model validation against SUPPORTED_MODELS
  - ✅ Cleaner error handling with custom exceptions

  Quantis Has:
  - ✅ SSE (Server-Sent Events) support via SSEHubClient
  - ✅ Crypto news detection and specialized handling
  - ✅ Token limit checking before processing
  - ✅ Asset document generation (generateAssetDocument())
  - ✅ Message-to-function mapping (deprecated, for fallback)
  - ✅ HTTP client caching as optimization
  - ✅ Standalone utility functions at file end

  7. Progress Reporting

  GPT:
  $this->sendProgress("Connecting to Claude API...");
  - Simple string messages to SSE client

  Quantis:
  if ($sseClient) {
      $sseClient->sendProgress('Claude: Executing function: ' .
  $contentBlock['name']);
  }
  - Conditional SSE support with null checks
  - More descriptive progress messages

  8. Usage Tracking

  GPT:
  $this->usageTracker?->trackRequest([
      'user_id' => $userId,
      'provider' => 'claude',
      // ...
  ]);
  - Via injected UsageTracker interface

  Quantis:
  private function trackUsage(...) {
      global $llm_system;
      $db = $llm_system['db'] ?? null;
      $stmt = $db->prepare("INSERT INTO llm_requests...");
  }
  - Direct SQL insertion using global DB connection
  - Fallback to config if global not available

  Summary

  GPT ClaudeProvider = Modern, clean, testable architecture with dependency
  injection and interfaces. Best practices oriented.

  Quantis PortfolioClaude = Feature-rich, practical implementation with SSE
  support, crypto news handling, and extensive debugging. More specialized but
  less maintainable.

  The GPT version is better structured but the Quantis version has more 
  features (SSE, crypto news, token limits, asset documents). Quantis
  sacrifices architecture for functionality and debugging visibility.
