# Ingestion Compiler — emit a standalone Python (langchain) script

> Companion to `2026-06-18-ingestion-execution-model.md` (the "two faithful
> lowerings"). The PHP **interpreter** is built; this is the **compiler** — it
> generates a self‑contained `.py` from the node configs. Discipline: **faithful
> lowering** — the script must produce the SAME chunks and vectors the
> interpreter does.

## 1. Shape

`IngestionCompiler` (PHP) is a **code generator**: dispatch‑table fragments per
node + a skeleton driver. "Add a backend = one fragment + one editor dropdown"
stays true. Every emit is validated with `py_compile`; the real safety net is a
**parity test** (run the emitted script AND the interpreter on the same folder,
assert equal chunk counts + a sampled chunk).

## 2. The three nodes in Python

**Splitter — pure langchain, faithful for free.**
```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
split = RecursiveCharacterTextSplitter(chunk_size=CHUNK, chunk_overlap=OVERLAP)
chunks = split.split_text(text)
```
This is the exact algorithm the PHP `IngestionSplitter` is parity‑tested against
→ identical chunks by construction.

**Loader — a thin custom component over the UniversalFS MCP** (NOT langchain's
built‑in loaders). The interpreter reads via UniversalFS (so it works for
S3/GDrive/etc.) and decodes with pypdf / docx2txt / html→markdown. We emit a
small `UniversalFSLoader` (shaped as a langchain `BaseLoader` for idiom):
`list_files` (recursive, type‑filtered) → `read_file` (base64) → decode. Using
langchain's `PyPDFLoader` etc. would only handle local files and decode
differently → drift, so we don't.

**Store — the one DECISION:**
- **(a) Faithful (default):** call the **`qdrant-store` MCP** (httpx, session
  handshake, server self‑embeds) → SAME vectors as the interpreter. Depends on
  the MCP server at run time.
- **(b) Portable (`--portable` variant):** `langchain_qdrant.QdrantVectorStore` +
  an EXPLICIT embeddings model — self‑contained, but you must pin the exact
  model the MCP uses (FastEmbed `all-MiniLM-L6-v2` / the Cloud Inference model)
  or vectors won't match.

Default to **(a)**; offer **(b)** later.

## 3. The loop

The interpreter's event loop lowers to a plain `for` (execution‑model §7):
`for f in files: store(split(load(f)))`. "Store clocks the loader" becomes loop
iteration.

## 4. Multi‑thread — Python collapses the PHP machinery

Everything hand‑built in PHP (shared cursor file, `flock` atomic claim, K worker
processes, work‑stealing) becomes `concurrent.futures`:
```python
from concurrent.futures import ProcessPoolExecutor
with ProcessPoolExecutor(max_workers=WORKERS) as ex:
    for src, n in ex.map(process_file, files):
        print(src, n)
```
- the executor's queue **is** the shared cursor → **work‑stealing for free**;
- **`ProcessPoolExecutor`** (real processes, bypass GIL) for CPU‑heavy decode
  (big PDFs); `ThreadPoolExecutor` when network‑bound. Compiler picks by file
  type, or defaults to processes;
- `WORKERS` = the loader's **Parallel workers** field (blank → `os.cpu_count()`).
- the thread‑id fan‑out (multi‑target branches) would be per‑branch functions;
  the worker pool needs no ids.

## 5. Emitted script (sketch)

```python
# generated by IngestionCompiler
import base64, httpx, io, pypdf, docx2txt
from concurrent.futures import ProcessPoolExecutor
from langchain_text_splitters import RecursiveCharacterTextSplitter

UFS, QDRANT = "<ufs_url>", "<qdrant_mcp_url>"
PROVIDER, PATH, TYPES = "local", "<path>", ["html","pdf"]
CHUNK, OVERLAP, COLLECTION, WORKERS = 1000, 150, None, 4

def ufs(tool, args): ...            # POST JSON-RPC, parse SSE/JSON
def enumerate_files(): ...          # recursive list_files, type-filter → descriptors
def read_file(p, fid): return base64.b64decode(ufs("read_file", {...}))
def decode(name, data): ...         # pypdf / docx2txt / html→md / utf-8

split = RecursiveCharacterTextSplitter(chunk_size=CHUNK, chunk_overlap=OVERLAP)

def qdrant_session(): ...           # initialize → Mcp-Session-Id
def qdrant_store(sess, text, src): ...   # tools/call qdrant-store {information, metadata}

def process_file(desc):             # runs in each worker process
    text   = decode(desc["name"], read_file(desc["provider"], desc["file_id"]))
    chunks = split.split_text(text)
    sess   = qdrant_session()
    for c in chunks: qdrant_store(sess, c, desc["source"])
    return desc["source"], len(chunks)

if __name__ == "__main__":
    files = enumerate_files()
    with ProcessPoolExecutor(max_workers=WORKERS) as ex:
        for src, n in ex.map(process_file, files):
            print(f"{src}: {n} chunks")
```

## 6. Build approach

1. **Rewrite `IngestionCompiler::compileScript`** to the interpreter's real
   semantics (the current one is stale — PGVector / local langchain loaders /
   single file). Keep the dispatch‑table structure: per‑node fragment + the
   `enumerate → ProcessPoolExecutor → process_file` skeleton.
2. The compile endpoint resolves the **store server url/headers** (from
   `store:"mcp:<id>"`) and the **UniversalFS url** (loader `storage_mcp_url`) and
   passes them in, so the emitted script is runnable.
3. **Validate** each emit with `py_compile`.
4. **Parity test** vs the interpreter (equal chunk counts + a sampled chunk).

## 6b. BUILT (v1) — 2026‑06‑19

`IngestionCompiler::compileScript($loader,$splitter,$store,$ctx)` rewritten to emit
exactly §5 (config interpolated as Python literals via `json_encode`). The
`compile` endpoint resolves `$ctx` = {`ufs_url` from loader `storage_mcp_url`,
`qdrant_url` from `store:"mcp:<id>"`→mcp_servers}. **Verified:** emit `py_compile`s
clean AND **runs end‑to‑end** — `cv/articles` (24 files) via a 4‑worker
`ProcessPoolExecutor` → 989 chunks stored → `qdrant-find` retrieves them.

**Decode is library‑dependent (the honest caveat):** PHP `smalot`/`league
html‑to‑markdown`/native‑docx vs Python `pypdf`/`markdownify`/`docx2txt` extract
text differently → chunk COUNTS differ (e.g. one HTML file = 16 chunks in the PHP
interpreter vs 26 in the compiled script). text/csv ARE byte‑identical; the
splitter + store contract ARE faithful. So "faithful" = same pipeline/semantics,
NOT byte‑identical chunks for binary/HTML. (`markdownify` not in the test venv →
the emitted script's HTML fallback is a crude regex strip; `pip install
markdownify` for better HTML.) The compiled script is the PRODUCTION artifact
(best libs per language); the interpreter is for authoring/preview.
